# 종목 활성 상태 마이그레이션

일일 자동 동기화를 활성화하려면 `002-stock-sync-run.sql`도 한 번 적용해야 합니다.
이는 실행 기록 테이블만 추가하며 기존 거래 테이블은 변경하지 않습니다.
001이 이미 적용된 DB에는 002만 추가합니다. 자동 실행 설정과 확인 방법은 `STOCK_SYNC.md`를 확인합니다.

새 WAR 배포 전에 승인된 대상 DB에 `001-stock-active.sql`을 한 번 적용합니다.
기존 종목은 모두 활성 상태로 시작하며 보유·주문·체결·실현손익 데이터는 변경하지 않습니다.
기존 DB에 전체 덤프 `db_schema/schema.sql`을 다시 적용하지 않습니다.
이 작업에서는 개발/운영 DB에 마이그레이션을 적용하지 않습니다.

배포 전 백업과 현재 `stock` DDL을 확인하고, 적용 후 `active` 컬럼의 기본값 1 및 기존 행 수를 확인합니다.
이미 컬럼이 있으면 재실행하지 않습니다. 이전 WAR로 복귀할 때 추가 컬럼은 유지할 수 있지만,
이전 버전의 동기화는 물리 삭제를 수행하므로 동기화 실행을 중지해야 합니다.
비활성 상태·취소된 주문의 자동 복원이나 삭제 이력 복구를 수행하는 rollback SQL은 제공하지 않습니다.

현재 동기화는 KIS의 코스피·코스닥 마스터를 모두 다운로드·파싱한 뒤 반영합니다.
공유 임시 파일과 `TRUNCATE temp_stock`은 사용하지 않습니다. 비활성은 목록 미등재 상태이며 상장폐지를 확정하는 의미가 아닙니다.
기본적으로 기존 활성 종목의 95% 이상이 새 목록에 남아야 반영합니다.
`stock.sync.minimum-retention-ratio`(0~1)로 이 비율을 설정할 수 있으며,
대량 누락이 정상인지 확인하지 않고 제한을 낮추면 안 됩니다.
이 검사는 부분 목록의 완전성을 증명하지 않으며, 유효한 소규모 누락까지 판별하지 못합니다.

누락 종목은 비활성화하고 남은 WAIT/PARTIAL 주문은 CANCEL로 변경합니다.
기체결·보유·손익은 유지하고 재등장한 종목도 취소된 주문을 재개하지 않습니다.
신규·정정·체결 SQL은 활성 종목만 허용합니다. 종목 상태 변경과 이미 진행 중인 체결의 동시성 전체는 별도 과제입니다.
보유 조회는 비활성 종목도 반환하며 가격·평가금액·평가손익이 없으면 null을 반환합니다.
화면은 해당 값과 합계 평가를 ‘평가 불가’로 표시하고 계좌 잔고와 보유 수량·매입금액은 보존합니다.
활성 종목의 외부 가격 조회 장애 전체에 대한 fallback은 별도 범위입니다.

테스트 Compose는 이 마이그레이션 파일을 초기화 단계에서 실행합니다.
`src/test/resources/db/init/01-schema.sql`은 컬럼 추가 전 stock DDL을 유지하여 실제 파일의 적용을 검증합니다.
테스트 스크립트 사용법은 `TESTING.md`를 확인합니다.

[코스피](https://github.com/koreainvestment/open-trading-api/blob/main/stocks_info/kis_kospi_code_mst.py)와
